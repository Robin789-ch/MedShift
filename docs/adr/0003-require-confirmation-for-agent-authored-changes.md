# Require confirmation for agent-authored changes

Every agent-authored add, update, or removal is prepared as one typed change set and shown to the user in domain language before it becomes active. Applying confirms and atomically commits the entire change set, while cancelling leaves the workspace unchanged; read-only agent responses require no confirmation. A proposal remains in the ephemeral conversation after either decision, with a deterministic Applied or Cancelled status so later turns know what became active. If a request has multiple plausible catalogue interpretations or targets, the agent asks for clarification and creates no pending change set. This deliberate extra interaction protects operational scheduling decisions from model misunderstanding and gives the user a visible review point.
